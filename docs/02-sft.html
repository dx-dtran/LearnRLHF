SFT and the loss mask

One loss, one mask, one off-by-one. All three have to be right.

1SFT is behavior cloning

Supervised finetuning is exactly pretraining's loss on different data: predict the next token, everywhere. What changes is which next-tokens you charge the model for. The dialogues contain two voices — the human's turns and the assistant's — and you only want to clone one of them. Train on the human's tokens too and you teach the model to continue asking questions, which is precisely the failure mode SFT exists to remove. This is the bug in the old repo, and problem 2.1 is where you fix it.

2The mask, on real tokens

Why does the assistant's <|im_end|> carry mask 1? Because stopping is a behavior. If the model is never trained to emit the end tag, it never learns to finish a reply — you will meet this again in PPO, where a rollout that never terminates eats your whole token budget.

3The shift by one

Logits at position t are a prediction of the token at position t+1. So labels is input_ids shifted left, and the mask must ride along with the label, not the input position. Get this wrong and the loss still goes down — you are just training every prediction against the wrong target, one token late. The unit test in 2.3 that hand-checks mask positions on a tiny example is what catches it.

4The gradient you should recognize on sight

For one position, cross-entropy through a softmax has the cleanest gradient in deep learning: ∂L/∂logits = p − onehot(target). The model's current belief, minus where the probability should have gone.

The masked SFT loss is this picture times mask, summed, divided by the number of masked-in tokens — not by sequence length. Divide by T and your effective learning rate silently depends on how chatty the human was.

Grad-check note — problem 2.2 Two tests, not one: the centered-difference check on the gradient, and the mask test — change a masked-out token's logits and assert the loss does not move at all. The second is the one that would have caught the old repo's bug.

5What success looks like

After two epochs, eval loss stops being the interesting metric. Generate side by side (problem 2.5): the base model answers a question with more questions or drifts into web boilerplate; the SFT model stays in the assistant role, answers, and stops. It will still be confidently wrong and occasionally unhelpful — SFT can only imitate the demonstrations it saw. Making it prefer better answers is what the next two modules are for.
