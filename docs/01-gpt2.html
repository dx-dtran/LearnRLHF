GPT-2 anatomy

What you should see in your head while writing model.py.

1The residual stream

The most useful mental model of a transformer is not "a stack of layers" but a residual stream: each token owns a vector of width C = 768, and that vector flows unchanged from bottom to top unless a block explicitly adds something to it.

Three consequences worth internalizing before problem 1.5:

  • Pre-LN placement. LayerNorm sits inside each branch (x + attn(ln(x))), so the stream itself is never normalized between blocks. The branch sees clean statistics; the highway stays untouched.
  • Attention is the only place tokens talk. The MLP is applied to each position independently. If information needs to move between positions, attention moved it.
  • Tied unembedding. The final projection to vocabulary logits reuses the token-embedding matrix, transposed. Reading out is the inverse of reading in.

2Attention is a soft lookup

Each position emits a query ("what am I looking for?"), and every position emits a key ("what do I contain?") and a value ("what will I hand over if matched?"). The output at a position is a weighted average of past values, weights given by softmax of query·key. The causal mask limits the lookup to the past — position t may only read positions ≤ t.

Notice how ball pulls from red and picked: the head is assembling "what is being picked up, and what is it like?" into the vector that will predict the next token. Real heads are messier, but this is the operation.

Gotcha — problem 1.3 Scale scores by 1/√dk (per-head dim, 64), not 1/√C. And apply the mask before softmax, not after — masking probabilities after softmax leaves rows that don't sum to 1 and a gradient path to the future.

3LayerNorm: same shape, fixed statistics

LayerNorm re-centers and re-scales each token's vector so it has mean 0 and variance 1 across the channel dimension, then applies a learned per-channel gain and bias. It is a per-token operation — no batch statistics, no interaction between positions.

That invariance is the point: whatever the residual stream has accumulated, each branch sees inputs at a standard scale. The learned gain and bias then let the network re-introduce any scale it actually wants — the erasure is undone-able, but now it is a choice made by parameters, not an accident of depth.

Grad-check note — problem 1.2 The interesting terms in the backward pass come from the mean and variance depending on every element: perturb one input channel and all outputs move. Your centered-difference check will catch a forgotten term instantly; that is why LayerNorm is the first thing the course makes you differentiate.

4MLP: the per-token half

The other branch is two linear layers with a GELU between: expand 768 → 3072, apply GELU, project back. It holds most of the parameters and does the per-token processing — "given what attention gathered here, compute something." GPT-2 uses exact GELU (the Gaussian CDF), not the tanh approximation; the difference is small but will show up when you diff your forward pass against HuggingFace in 1.7.

5Loading the real weights

Problem 1.7 is bookkeeping, and the bookkeeping has one famous trap:

Gotcha — Conv1D HF's GPT-2 stores c_attn, c_proj, c_fc as Conv1D, whose weight is the transpose of an nn.Linear weight. Copy without transposing and the model still runs — shapes are square for c_proj — and generates plausible-looking garbage. The parity test (max abs diff < 1e-4 against HF's forward) is your only defense.

6Sampling: shaping the next-token distribution

Generation is just: forward pass, get a distribution over 50k tokens, pick one, repeat. The knobs in problem 1.8 all reshape that distribution before you sample. This matters later — PPO rollouts sample at temperature 1 from the raw distribution, and entropy collapse (Module 4) is literally this picture narrowing to a spike.

Two edge cases your generate() must handle: temperature → 0 becomes argmax (guard the division), and top-p must always keep at least one token even when the best token alone exceeds p.
